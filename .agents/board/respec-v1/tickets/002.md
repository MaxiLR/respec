## Goal

Profile switching: `respec use <profile>` and `respec status`.

## Acceptance criteria

- `use` symlinks every enabled skill of the profile into each of its targets' folders (copy fallback when symlinking fails), and records every created path in `state.json`.
- First time respec takes over a target folder, its full existing contents are backed up to `~/.respec/backups/<timestamp>/<target>/` before anything changes; installing respec alone changes nothing.
- Switching removes every path the previous profile created in every folder (including folders the new profile does not target), then installs the new profile into its own targets only.
- Scenario: A targets claude-code+agents, B targets oh-my-pi; after `use B`, the claude-code and agents folders contain none of A's items.
- Disabled skills are never linked.
- Removal only touches paths recorded in `state.json`; profile folders are never deleted by a switch.
- `status` (and `--json`) shows active profile, targets, linked items per folder.

## Testing seam

Temporary home with pre-populated fake target folders; assert filesystem state, backups and `state.json`.

## Exclusions

Unknown-item handling (004), interruption recovery (003), restore (005).
