## Design calls made (narrow, recommended option applied)

1. `use --unknown <choice>` and the switch prompt cover only the entries in the way. Other entries only warn. The first-takeover prompt is the exception: on a terminal it asks about every entry already in the new folder. With `--unknown` on a terminal, that choice also applies to takeover entries. Off a terminal, takeover entries only warn.
2. On a first takeover, the full-folder backup happens before any entry is resolved, so `respec restore` still returns the exact original folder. When the dialog or prompt is used, the switch takes over the folder first. If an entry then stays unresolved, the switch is refused but the folder stays owned. If no handler is given, nothing changes.
3. `-p` was removed from `respec adopt` and `respec restore`, so add always targets the active profile, matching criterion 1. The internal `resolve(profile=...)` still takes any profile, because a takeover during `use` adds to the profile being left.
4. The overwrite in criterion 5 applies only when the entry is flagged `replaced` and the target profile already has a skill of that name. Any other name clash still fails safely, as before. The profile's `source` record is kept, so a later `update` sees local edits and asks before overwriting them.
5. Only `.DS_Store` is excluded from `digest()`. Other dotfiles inside a skill still count as edits.

## Concerns

- On a terminal, the restore "Back these up and overwrite them?" confirm is now effectively unreachable. Every unknown entry gets an add or remove prompt first, so `--overwrite` remains the non-interactive route. The confirm was left in place rather than widening scope.
- An edited copy of an enabled skill in the active profile blocks every refresh of that profile until it is resolved, because respec would replace that path. This follows criterion 2, which says such paths block, and the message names the path and `respec adopt`.
- The TUI cancel test and the "entry appearing after the dialog opened" test now use entries at install paths, because entries elsewhere no longer open the dialog.
- `tests/test_layers.py::test_switch_refused_when_preflight_blocks_leaves_profile_unchanged` passes unchanged, because the new message keeps "not managed by respec". fix-5 also touches layer tests, so a merge conflict there is possible, but `layers.py` and `profiles.py` were not edited here.
