## Concerns

- Files inside a fetched skill that are symlinks are still followed by `shutil.copytree` (unchanged default). A malicious repo could make respec copy a local file (for example `SKILL.md -> ~/.ssh/id_rsa`) into the profile folder. Nothing is sent anywhere, but the file becomes readable as skill content. Not in the review's scope; a follow-up could reject symlinks resolving outside the item.
- `_git` now also drops `GIT_CONFIG_PARAMETERS`/`GIT_CONFIG_COUNT` (part of git's local-env list), so `git -c` settings from a parent process do not reach respec's git calls. `GIT_CONFIG_GLOBAL`/`GIT_CONFIG_NOSYSTEM` are kept.
- N3: after a non-`SwitchBlocked` refresh failure, the update stays applied (new files plus new commit in `profile.yaml`), and `state.json` follows the switch engine's journal, as the reviewer described.
