### Findings (none block the merge)

1. **`.DS_Store` inside a copy marks it replaced (new, minor).** `digest`
   includes hidden files. `unknown` ignores hidden entries at the folder level,
   but not inside a copied item. I confirmed it with a probe: writing
   `tdd/.DS_Store` into a managed copy turns it into unknown, `replaced=True`,
   and the next switch or item edit is blocked until the user chooses. On
   macOS, Finder can create this file. It is a false positive, not data loss.
   One option is to skip hidden names inside `digest`, matching the
   folder-level rule.
2. **Copies recorded before fix-1 are now unknown (new, minor).** A copy record
   without `digest` is never managed. The docstring says this is intended, and
   it is the safe direction. I confirmed it with a probe: after stripping
   `digest` from state.json, the copy becomes unknown/`replaced`. No shipped
   state files should be affected yet.
3. **`use --json` output shape (new, minor drift).** `cli.py:295` still
   serializes with `vars(item)`, so `installed` entries in `use --json` now
   always include `"digest": null` for symlinks. state.json goes through
   `Installed.to_dict()` and leaves it out. The spec makes `--json` the
   machine-readable contract (spec.md:123). The two outputs should use one
   serializer, `to_dict()`.
4. **Long docstring line.** `src/respec/state.py:30` is 97 columns. Black
   passes because it does not reflow docstrings. Cosmetic.
5. **Still open from int-60224c7 (not fix-1's scope):** duplicate helper
   `switch._real` (switch.py:92) and `unknown.real` (unknown.py:45). The
   registry-order sort is duplicated in `switch.status` and
   `unknown.folder_groups`. adopt.py uses the private `switch._utc_now` and
   `switch._new_backup_run`. Item and layer edits blocked by unknown entries
   show the misleading "cannot switch… pass '--unknown' to 'respec use'"
   message. `state.unmanaged` is never pruned. fix-1 added no new duplicate
   helpers: `digest` exists only in unknown.py, and switch.py calls it through
   `unknown.`.
